# 公网上线清单（部署到服务器时照此执行）

> 本目录与仓库根部的 `docker-compose.yml` 配套。**本地开发不使用本目录任何文件**，本地依旧是 http://localhost:5000。
> 在没有明确指示前，AI 助手不会执行任何服务器部署操作；本清单由你在服务器上手动逐项执行。

具体服务器信息、历史升级与回滚记录仅保存在维护者本机的 `docs/`，不随代码仓库发布。

## 适用范围

以下清单只适用于新的独立服务器。已有实例或共享反向代理环境应沿用既有部署方式，不得直接照搬首次上线命令重建服务。

## 0. 前置条件（缺一不可）

- [ ] 公网服务器一台（云主机），已安装 Docker 与 Docker Compose v2
- [ ] 一个域名；服务器在中国大陆时域名必须完成 ICP 备案（否则 80/443 会被服务商拦截），境外服务器可免备案但国内访问延迟略高
- [ ] 域名 A 记录已解析到服务器公网 IP
- [ ] 公众号（订阅号/服务号均可接收消息）管理员权限

## 1. 首次配置

- [ ] 生成强随机 Token：`openssl rand -hex 16`，写入服务器项目目录 `.env` 的 `WECHAT_TOKEN`（公网绝不使用默认值 mywechat2025）
- [ ] 确认 `.env` 中 `WECHAT_APPID` 与公众号后台一致
- [ ] 设置 `DOMAIN=你的域名`、`ACME_EMAIL=你的邮箱`（证书到期通知）
- [ ] `chmod 600 .env`；该文件已在 .gitignore，永不入库

## 2. 启动

- [ ] 在项目根目录执行：

  ```
  docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
  ```

- [ ] Caddy 会占用 80/443 并自动申请与续期 Let's Encrypt 证书
- [ ] 应用仅绑定 127.0.0.1:5000，公网只能通过 https 访问

> 若 Docker Compose 版本较旧、不支持 `ports: !override` 语法：手动把根目录 docker-compose.yml 中 app 的 ports 改为 `"127.0.0.1:5000:5000"` 后，仅启动基础文件（此时无自动证书，需自备反代）。

## 3. 首次初始化（存在抢注窗口，部署后立即执行）

- [ ] 打开 `https://你的域名/console`
- [ ] 在公众号发送【验证码】，将收到的 6 位码填入登录页
- [ ] 首个登录的账号自动成为管理员；之后注册的都是普通用户
- [ ] 初始化完成前存在陌生人抢注管理员的窗口期，请部署后立即完成本步骤

## 4. 公众号后台服务器配置

- [ ] 公众号后台 → 设置与开发 → 基本配置 → 服务器配置 → 修改配置
- [ ] URL 填 `https://你的域名/wechat`
- [ ] Token 填与服务器 `.env` 中 `WECHAT_TOKEN` 完全一致的值
- [ ] 消息加解密方式选「明文模式」（当前代码按明文实现）
- [ ] 提交并启用（微信会发起 GET 签名校验，通过即生效）

## 5. 上线验证

- [ ] 浏览器访问 `https://你的域名/console` 正常打开，证书有效无告警
- [ ] 真实微信关注公众号，能收到欢迎语
- [ ] 管理员登录控制台正常
- [ ] 在沙箱或业务站走一遍发码与核销全流程
- [ ] 停用一个项目后，该项目发码应被拒绝（隔离生效）

## 6. 常驻安全与运维

- [ ] 防火墙/安全组仅放行 22、80、443；5000 端口不对公网开放
- [ ] Redis 不暴露公网（基础文件中仅绑定宿主机 127.0.0.1）
- [ ] 定期备份：服务器上的 `config/` 目录（账号与激活码账本）与 `redis_data` 数据卷
- [ ] 版本升级：先确认当前部署方式并备份，再沿用原有镜像或源码部署流程更新；不得把首次上线命令直接用于已有共享代理实例，不改变数据挂载或清空配置、Redis。

## 7. 常见问题

- 握手失败 / Token 校验不通过：检查 `.env` 的 `WECHAT_TOKEN` 与公众号后台是否完全一致、证书是否有效
- 收不到消息：公众号后台服务器配置未启用，或 URL 不是 `https://你的域名/wechat`
- 80/443 无法访问：大陆服务器域名未备案，或安全组未放行
- 管理员无法登录：先检查备份、账号状态与会话，保留全部配置和永久编号映射；不得通过删除 `accounts.json`、清空 `config/` 或 Redis 来重新抢注管理员。
